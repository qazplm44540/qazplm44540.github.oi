# 锐今阁新中式女装买手店网站产品需求文档 (PRD)

## 1. Goals and Background Context

### 1.1 Goals
*   构建一个极具视觉冲击力与文化叙事性的线上品牌空间，精准传达“柔古锐今，解构新生”的品牌哲学。
*   为目标用户（18-40岁先锋文化追求者）提供沉浸式的浏览体验，引导其产生情感共鸣与线下到店预约。
*   通过4个核心功能页面（首页、单品页、分类页、空间页），在纯前端技术约束下，实现高性能、高美感的响应式网站。
*   建立可衡量的成功指标框架，包括品牌认知度、用户参与度及线下导流转化率。

### 1.2 Background Context
当前新中式服装的线上呈现普遍陷入传统守旧或完全西化的两极，缺乏能融合“古典材质”与“先锋剪裁”这一核心冲突美学的数字表达。锐今阁作为一个具有鲜明审美主张的买手店，其线上平台不仅是展示窗口，更是品牌理念的延伸。本项目旨在通过解构主义的设计语言和现代Web技术，打造一个打破常规、能引发目标用户深度共鸣的网站，弥补市场空白，并有效连接线上体验与线下消费。

## 2. Requirements

### 2.1 Functional Requirements
**FR1：品牌叙事与视觉冲击首页**
*   FR1.1：网站必须包含一个全屏视觉冲击区域，通过动态图形、文字排版或视频背景，直观传达“柔古锐今，解构新生”的品牌核心哲学。
*   FR1.2：首页必须包含一个动态网格布局的热卖单品推荐区域，至少展示6件单品，并支持悬停交互以显示更多信息（如名称、价格）。
*   FR1.3：首页必须包含一个时间轴或横向滚动形式的新品展示区，清晰指示上新节奏，点击可跳转至对应单品或分类。
*   FR1.4：网站必须具备一个响应式导航菜单，在所有设备上清晰易用，并体现解构主义设计风格。

**FR2：沉浸式单品展示页**
*   FR2.1：每个单品必须拥有独立的展示页面，包含高清主图、名称、价格、详细描述（材质、剪裁、设计灵感）。
*   FR2.2：单品页的背景色或主题元素必须能根据单品的主色调或季节主题进行动态变化，营造氛围。
*   FR2.3：必须提供一种交互方式（如鼠标悬停、拖动），通过CSS 3D变换模拟展示单品面料的三维质感或不同角度。
*   FR2.4：必须提供一个可展开/折叠的“文化叙事”面板，详细阐述该单品的设计灵感来源、与传统元素的解构关系。

**FR3：诗意化季节分类与筛选页**
*   FR3.1：必须提供按“春、夏、秋、冬”四季分类的导航入口，每个入口需有独特的视觉标识（色彩、图形）。
*   FR3.2：必须提供动态筛选功能，允许用户混合筛选条件（季节、材质类型、剪裁风格），并实时更新展示结果。
*   FR3.3：分类页应包含一个视觉化的日历时间轴导航，用户可通过点击时间点快速跳转到不同季节或月份的新品集合。
*   FR3.4：在季节间切换或滚动时，页面应有流畅的主题色彩过渡动画效果。

**FR4：线下空间导流与预约页**
*   FR4.1：必须展示线下门店的详细介绍、环境图片、具体地址、联系电话和营业时间。
*   FR4.2：必须提供一种360°空间预览体验，可通过多图片序列动画或CSS变换模拟实现。
*   FR4.3：必须集成一个前端预约到店表单，收集用户姓名、联系方式、预约时间及备注，并具备前端基础验证（非空、邮箱/电话格式）。
*   FR4.4：必须提供富有诗意和美感的导航指引（如结合周边文化地标的地图描述），而不仅仅是标准地图插件。

**FR5：数据与内容管理**
*   FR5.1：所有单品数据（图片、信息）必须通过本地JSON文件进行管理，便于非技术人员通过编辑文本文件进行更新。
*   FR5.2：网站必须能正确读取并渲染JSON文件中的所有数据，无硬编码内容。

### 2.2 Non-Functional Requirements
**NFR1：性能**
*   NFR1.1：在4G网络环境下，网站的首次内容绘制（FCP）必须小于1.5秒，完全加载时间小于3秒。
*   NFR1.2：所有动画与交互（包括复杂CSS动画）必须保持每秒60帧（60fps）的流畅度。
*   NFR1.3：累积布局偏移（CLS）必须小于0.1，确保视觉稳定性。

**NFR2：兼容性与响应式**
*   NFR2.1：网站必须在最新版本的Chrome、Safari、Firefox桌面浏览器中功能与视觉完全正常。
*   NFR2.2：网站必须在iOS Safari和Android Chrome最新版本上提供良好体验，核心功能可用。
*   NFR2.3：网站必须完美适配从手机（最小宽度320px）到桌面（最大宽度1920px及以上）的各类屏幕尺寸，布局、字体大小、图片均能自适应。

**NFR3：技术栈与质量**
*   NFR3.1：必须仅使用纯HTML5、CSS3（含Grid、Flexbox、Custom Properties等）和原生JavaScript（ES6+）开发，不得引入任何前端框架（如React, Vue）或UI库。
*   NFR3.2：代码结构必须清晰，HTML语义化，CSS模块化，JavaScript函数职责单一，并包含必要注释。
*   NFR3.3：必须使用Git进行版本控制，并包含有意义的提交信息。

**NFR4：可维护性与SEO**
*   NFR4.1：网站应具备基本的SEO结构，包括语义化HTML标签、合理的标题（H1-H6）、图片Alt属性、以及简洁的Meta描述。
*   NFR4.2：项目文件结构应清晰，分离HTML、CSS、JS、图片和JSON数据文件，便于后续维护和扩展。

## 3. User Interface Design Goals

### 3.1 Overall UX Vision
打造一个“可游可居”的数字化美学空间。用户体验应像漫步在一个解构主义艺术馆中：路径非对称但充满惊喜，材质对比强烈但和谐，每一处交互都透露着文化叙事。导航本身即是探索的一部分，鼓励用户发现而非直接寻找。

### 3.2 Key Interaction Paradigms
*   **冲突与融合**：交互中体现“古”与“今”的冲突（如传统纹样的几何化动画、毛笔字与无衬线字的切换）。
*   **材质感知**：通过视觉和微交互模拟丝绸、棉麻、金属等不同材质的质感。
*   **非线性导航**：允许用户通过非线性的方式（如时间轴、视觉关联）浏览内容，而非仅靠层级菜单。
*   **渐进式披露**：信息按需呈现，保持界面洁净，通过悬停、点击展开更多细节。

### 3.3 Core Screens and Views
1.  **首页（美学宣言）**：品牌核心理念的视觉化总览，通往其他功能的诗意入口。
2.  **单品详情页（深度叙事）**：聚焦单件服装，融合商品信息与文化故事。
3.  **季节分类页（诗意发现）**：以时间和自然为主题的组织方式，引导用户探索系列。
4.  **线下空间页（虚实连接）**：实体店的数字孪生，促成线下预约的关键转化点。

### 3.4 Accessibility: WCAG AA
在保持前卫视觉的同时，需满足WCAG AA级无障碍标准。确保有足够的色彩对比度（文本与背景），为所有非文本内容（如图片、图标）提供文本替代方案，确保所有功能均可通过键盘访问，并保持焦点指示清晰。

### 3.5 Branding
*   **色彩**：主色调应源于中国传统色彩（如黛蓝、赭石、竹青），但饱和度与明度需经现代调整，并与高对比度的中性色（黑、白、高级灰）搭配。
*   **字体**：结合使用一款具有书法韵味的中文字体（用于标题、引言）和一款现代、简洁的无衬线字体（用于正文），形成鲜明对比。
*   **图形与纹理**：运用解构的传统纹样（如破碎的云纹、几何化的窗棂）、材质拼贴（丝绸与混凝土的质感对比）作为视觉元素。
*   **动效风格**：动画应模仿自然材质运动（如丝绸飘落、水墨晕开）或具有机械精密感，避免卡通化效果。

### 3.6 Target Device and Platforms: Web Responsive
优先设计桌面端体验以充分展现视觉复杂性，但必须确保在移动端（触控交互）有同样流畅、直观且经过适配的体验。网站需在各种屏幕尺寸上都能保持其品牌识别度和核心交互。

## 4. Technical Assumptions

### 4.1 Repository Structure: Monorepo
采用单仓库结构。所有前端代码、资产、数据文件和项目文档均位于同一仓库中，便于管理和部署。
*   **理由**：项目为纯静态网站，无多服务端组件，单仓库结构简单直接，与静态托管平台工作流匹配最佳。

### 4.2 Service Architecture
纯静态网站架构。无服务器端逻辑，所有页面在构建时生成或直接为HTML文件。动态交互由客户端JavaScript处理，数据来自静态JSON文件。表单提交通过第三方无服务器服务（如Formspree、Netlify Forms）或轻量级云函数处理。
*   **理由**：完全符合简报“纯HTML、CSS、JavaScript”的技术约束，最大化性能，降低成本，简化运维。

### 4.3 Testing Requirements: Unit + Integration
*   **单元测试**：针对核心的、复杂的JavaScript功能模块（如数据加载、筛选逻辑）编写单元测试（使用Jest等框架）。
*   **集成/E2E测试**：对关键用户流程（如导航到单品页、使用筛选器、提交预约表单）进行端到端测试（使用Cypress或Playwright）。
*   **手动测试**：由于设计高度视觉化，需要大量手动视觉回归测试和跨浏览器兼容性测试。
*   **理由**：确保核心逻辑正确性和关键业务流程的可靠性，同时承认视觉测试自动化的难度。

### 4.4 Additional Technical Assumptions and Requests
*   **CSS架构**：建议使用CSS Custom Properties (CSS变量) 构建一套完整的设计令牌系统（色彩、字体、间距、动画时长），以确保整个网站设计的一致性和易于主题切换。
*   **JavaScript模块**：使用ES6 Modules组织代码，按功能划分（如`dataFetcher.js`, `filterManager.js`, `formHandler.js`）。
*   **构建与部署**：虽然可以是纯静态，但建议引入极简的构建步骤（如使用Parcel或Vite）以享受代码分割、资源优化、开发服务器热重载等便利，并部署到Vercel/Netlify。
*   **第三方集成**：
    *   **表单提交**：集成如Formspree或Netlify Forms的服务，实现无后端表单处理。
    *   **地图**：如需，使用Mapbox GL JS或类似提供更定制化、美观的地图展示，以符合网站风格。
*   **图片优化**：所有图片必须经过压缩，并考虑使用`<picture>`元素和`srcset`属性提供响应式图片。

## 6. Epic Details

### 6.1 Epic 1: 项目奠基与核心视觉系统
**Epic Goal**：搭建稳健、可维护的技术地基，并确立贯穿整个网站的“柔古锐今”视觉设计语言。确保开发环境就绪，基础组件可用，数据流畅通。

#### Story 1.1 项目初始化与开发环境搭建
*   **As a** 开发者，
*   **I want** 初始化项目仓库、设置代码结构、配置必要的开发工具（如构建工具、代码格式化、Git Hooks），
*   **so that** 我能有一个高效、规范的开发起点，并确保代码质量。
*   **Acceptance Criteria**:
    1.  Git仓库初始化，包含合理的`.gitignore`文件。
    2.  选择并配置一个极简的构建工具（如Vite）以支持ES6模块、开发服务器和基础构建。
    3.  配置好代码格式化和基础lint规则。
    4.  项目根目录下建立清晰的文件夹结构（如 `/src`, `/public`, `/data`, `/docs`）。
    5.  在`README.md`中记录项目设置和开发命令。

#### Story 1.2 品牌视觉系统（设计令牌）实现
*   **As a** 开发者兼设计师，
*   **I want** 在CSS中定义一套完整的设计令牌（色彩、字体、间距、边框、动画曲线等），
*   **so that** 全站样式保持高度一致，且未来调整主题变得非常容易。
*   **Acceptance Criteria**:
    1.  在CSS中使用`:root`定义所有设计令牌变量。
    2.  颜色变量包括品牌主色、辅助色、中性色及状态色，均源自简报中的中国传新色。
    3.  字体变量至少包含标题字体和正文字体两类。
    4.  间距、边框半径、阴影、动画时长等均有标准化变量。
    5.  创建一个简单的“风格指南”测试页面，展示所有设计令牌的应用效果。

#### Story 1.3 响应式布局框架与基础组件
*   **As a** 前端开发者，
*   **I want** 实现网站通用的响应式布局容器和基础UI组件（如按钮、链接、卡片），
*   **so that** 后续页面开发可以基于这些可复用的部件快速构建。
*   **Acceptance Criteria**:
    1.  实现一个响应式的页面布局容器，能适配从移动端到桌面端的各种宽度。
    2.  创建基础按钮样式，包含常规、悬停、激活状态，并符合品牌色彩。
    3.  创建基础卡片样式，用于承载内容。
    4.  所有组件需使用CSS Grid/Flexbox实现，并充分测试其响应式表现。

#### Story 1.4 解构主义响应式导航菜单
*   **As a** 用户，
*   **I want** 在任何设备上都能清晰、便捷地访问网站的主要区域，
*   **so that** 我可以轻松探索网站内容。
*   **Acceptance Criteria**:
    1.  实现一个具有“解构”视觉风格（如非对称、特殊分隔线）的导航栏。
    2.  导航在桌面端为横栏，在移动端可转换为汉堡菜单或类似的适应式设计。
    3.  导航链接包括：首页、分类、空间，并高亮当前所在页面。
    4.  导航交互平滑，移动端菜单的打开/关闭有动画效果。

#### Story 1.5 静态数据加载模块
*   **As a** 开发者，
*   **I want** 实现一个JavaScript模块，能够从本地的JSON文件中异步加载单品和分类数据，
*   **so that** 网站内容可以动态渲染，而不需要硬编码在HTML中。
*   **Acceptance Criteria**:
    1.  创建 `data/products.json` 和 `data/categories.json` 文件结构示例。
    2.  编写 `dataLoader.js` 模块，提供 `fetchProducts()`, `fetchProductById(id)` 等方法。
    3.  模块能处理加载中和加载错误状态。
    4.  在某个测试页面成功调用该模块并渲染出部分数据。

### 6.2 Epic 2: 品牌首页与单品展示核心体验
**Epic Goal**：打造网站最具标志性的两个页面——品牌宣言式的首页与深度沉浸的单品页，确立网站的核心用户体验和视觉标杆。

#### Story 2.1 全屏品牌视觉冲击区域
*   **As a** 首次访问用户，
*   **I want** 一进入网站就被强烈、独特的品牌视觉和口号所吸引，
*   **so that** 我能立即感知到锐今阁“柔古锐今，解构新生”的独特定位。
*   **Acceptance Criteria**:
    1.  首页顶部为全屏高度的视觉区域。
    2.  该区域结合动态图形（CSS动画）、艺术排版和可能的背景视频/图片，营造冲击力。
    3.  品牌核心标语清晰醒目地呈现。
    4.  该区域在移动端有适配版本，保持视觉张力。

#### Story 2.2 动态网格热卖推荐区
*   **As a** 潜在顾客，
*   **I want** 快速浏览到当前精选的热卖单品，
*   **so that** 我能发现可能感兴趣的商品。

#### Story 2.3 时间轴式新品横向滚动展示
*   **As a** 关注时尚潮流的用户，

*   **Acceptance Criteria**:
    1.  实现一个水平滚动的时间轴或卡片流区域。
    2.  该区域展示标记有“新品”属性的单品，并按时间排序。
    3.  视觉上清晰指示时间流向（过去->现在->未来）。
    4.  点击新品卡片可跳转至单品页。

#### Story 2.4 单品详情页基础结构与动态主题
*   **As a** 对某单品感兴趣的用户，
*   **I want** 查看该单品的所有详细信息，
*   **so that** 我能全面了解这件商品。
*   **Acceptance Criteria**:
    1.  页面布局清晰，展示单品主图、名称、价格、详细描述。
    2.  页面背景色或主题装饰元素能根据单品数据中的“主题色”字段动态变化。
    3.  页面URL应包含单品ID，支持直接链接访问。
    4.  页面信息全部从`products.json`动态加载。

#### Story 2.5 3D材质预览交互
*   **As a** 注重材质的顾客，
*   **I want** 在线感受服装面料的质感，
*   **so that** 我能更好地评估商品的品质和外观。
*   **Acceptance Criteria**:
    1.  在单品页提供面料区域的特定图片或图形。
    2.  通过鼠标拖拽或移动，触发该区域的CSS 3D旋转变换，模拟不同角度光照下的质感。
    3.  交互需平滑，性能良好。
    4.  在触摸设备上，支持相应的触摸手势。

#### Story 2.6 文化叙事展开面板
*   **As a** 看重设计故事的用户，
*   **I want** 深入了解这件衣服背后的设计灵感和文化内涵，
*   **so that** 我与品牌建立更深的情感连接。
*   **Acceptance Criteria**:
    1.  在单品页提供一个“设计故事”或“文化叙事”的触发按钮/区域。
    2.  点击后，以模态框、侧滑面板或页面内展开的形式，显示详细的叙事文本。
    3.  叙事内容来自`products.json`中的数据字段。
    4.  面板的关闭交互清晰易用。

### 6.3 Epic 3: 分类发现与线下导流
**Epic Goal**：完成用户发现内容的分类系统，并搭建连接线上与线下的关键桥梁——空间预约页，实现网站的核心商业目标。

#### Story 3.1 四季分类导航与视觉标识
*   **As a** 用户，
*   **I want** 直观地通过季节主题来浏览服装系列，
*   **so that** 我能根据自己的喜好或当下季节寻找合适的衣服。
*   **Acceptance Criteria**:
    1.  在分类页有清晰的“春、夏、秋、冬”四个入口。
    2.  每个季节入口有独特的色彩、图形或纹理作为视觉标识。
    3.  点击季节入口，页面内容（背景、标题）会相应切换为该季节主题。
    4.  默认显示当前季节或“全部”分类。

#### Story 3.2 动态混合筛选功能
*   **As a** 有明确偏好的用户，
*   **I want** 结合多个条件（如季节、材质、剪裁）来精确筛选商品，
*   **so that** 我能快速找到符合我所有要求的单品。
*   **Acceptance Criteria**:
    1.  提供一组可勾选的筛选器，至少包括季节、材质、剪裁风格。
    2.  选择多个筛选条件时，单品列表会实时更新，显示同时满足所有条件的商品。
    3.  被选中的筛选器有视觉反馈，并提供“清除所有”的选项。
    4.  筛选功能在移动端以适应方式呈现（如下拉面板、底部表单）。

#### Story 3.3 视觉日历时间轴导航
*   **As a** 对品牌历史或系列时间线感兴趣的用户，
*   **I want** 通过一个可视化的时间线来浏览不同时期的产品，
*   **so that** 我能感受品牌的演进和系列故事。
*   **Acceptance Criteria**:
    1.  在分类页集成一个水平或垂直的视觉时间轴。
    2.  时间轴上标记关键时间点（如“2024春夏”、“2024秋冬”）。
    3.  点击时间点，页面内容（或筛选器）会切换到对应时期的产品。
    4.  时间轴的视觉设计与网站整体风格一致。

#### Story 3.4 线下空间信息展示与360°预览
*   **As a** 考虑前往实体店的用户，
*   **I want** 详细了解门店的环境、位置和特色，
*   **so that** 我能判断是否值得前往以及如何前往。
*   **Acceptance Criteria**:
    1.  空间页清晰展示门店地址、联系电话、营业时间、简短介绍。
    2.  展示多张高质量的门店内景图片。
    3.  实现一个“360°预览”交互，用户可通过拖动鼠标或滑动屏幕环绕查看空间的多角度图片序列。
    4.  预览交互流畅，加载迅速。

#### Story 3.5 诗意化导航指引与预约表单
*   **As a** 决定前往实体店的用户，
*   **I want** 获得有创意且清晰的到店指引，并能方便地预约到店时间，
*   **so that** 我的到店体验是顺畅且有期待的。
*   **Acceptance Criteria**:
    1.  提供超越标准地图的指引，例如结合周边地标、文化景点或诗意描述的导航文案。
    2.  集成一个美观的预约表单，字段包括：姓名、电话/邮箱、期望到店日期与时间、备注。
    3.  表单具备基础前端验证（字段非空、联系方式格式）。
    4.  表单样式符合网站整体设计语言。

#### Story 3.6 预约表单前端验证与提交集成
*   **As a** 提交预约的用户，
*   **I want** 我的预约信息能被可靠地接收，并得到明确反馈，
*   **so that** 我能确认预约是否成功。
*   **Acceptance Criteria**:
    1.  前端验证失败时，在对应字段旁给出明确错误提示。
    2.  表单提交时，显示“提交中”状态，防止重复提交。
    3.  表单数据通过AJAX提交到配置好的后端服务（如Formspree端点）。
    4.  提交成功或失败后，在页面给出清晰的成功感谢信息或错误提示。

### 6.4 Epic 4: 优化、测试与部署
**Epic Goal**：对网站进行打磨，确保其性能、稳定性、兼容性达到上线标准，并成功部署到生产环境。

#### Story 4.1 全面跨浏览器与响应式测试
*   **As a** 项目负责人，
*   **I want** 确保网站在所有目标浏览器和设备上表现一致且功能正常，
*   **so that** 所有潜在用户都能获得合格的体验。
*   **Acceptance Criteria**:
    1.  在Chrome, Safari, Firefox最新桌面版中测试所有页面和交互。
    2.  在iOS Safari和Android Chrome上测试所有触控交互和响应式布局。
    3.  在多种屏幕尺寸（手机、平板、笔记本、大屏显示器）上验证布局和字体可读性。
    4.  记录并修复发现的所有主要兼容性问题。

#### Story 4.2 性能分析与优化
*   **As a** 追求卓越体验的开发者，
*   **I want** 确保网站加载迅速、运行流畅，
*   **so that** 用户不会被性能问题劝退。
*   **Acceptance Criteria**:
    1.  使用Lighthouse或WebPageTest进行性能测评，针对移动端和桌面端。
    2.  优化图片资源（压缩、使用WebP格式、懒加载）。
    3.  压缩和最小化CSS、JavaScript文件。
    4.  确保核心网页指标（FCP, LCP, CLS）达到或超过NFR中设定的目标。

#### Story 4.3 SEO基础优化与社交媒体元标签
*   **As a** 品牌主理人，
*   **I want** 网站能在搜索引擎中有良好的能见度，并在社交媒体分享时呈现美观的预览，
*   **so that** 能吸引更多潜在客户。
*   **Acceptance Criteria**:
    1.  为每个页面设置独特且包含关键词的`<title>`和`<meta name="description">`。
    2.  确保所有图片都有描述性的`alt`属性。
    3.  使用语义化HTML标签（`<header>`, `<main>`, `<section>`, `<article>`等）。
    4.  设置Open Graph和Twitter Card元标签，使链接在社交媒体分享时有正确的标题、描述和图片。

#### Story 4.4 生产环境构建与部署
*   **As a** 运维人员，
*   **I want** 将优化后的网站代码可靠地部署到生产托管环境，
*   **so that** 网站能够公开访问并稳定运行。
*   **Acceptance Criteria**:
    1.  配置生产环境构建脚本，执行所有优化步骤（压缩、资源哈希等）。
    2.  将构建产物部署到选定的静态托管平台（如Vercel）。
    3.  配置自定义域名（如果适用）并确保HTTPS启用。
    4.  进行上线后的最终冒烟测试，确认所有核心功能在生产环境中工作正常。
